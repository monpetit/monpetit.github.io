프로그래밍 언어를 배우다가 보면 한 두 군데서 개념적으로 막히는 부분이 있다. 예를 들면 Haskell의 Monad가 그렇고, Rust의 스마트 포인터, Trait 등이 그렇다.
하긴 생각해 보면 `async/await` 개념이 처음 소개되었을 때 사람들이 살짝 어려워했던 것 같기도 하다. 솔직히 말해 Javascript를 매일 같이 다루는 프론트엔드
개발자들 중에서 비동기 개념을 정확하게 이해하고 사용하는 사람들이 얼마나 있을까 싶긴 하다. 그리고 보니 비동기보다 더 이전, 멀티코어 시대에 들어오면서 처음 Thread 개념을
접했을 때에도 쉬운 일은 아니었다. 병렬적으로 뭔가를 수행한다는 개념이 어려운 게 아니라 Mutex, Semaphore가 프로그래머들을 괴롭히지 않았던가.

그러나 이런 모든 것들 중에 끝판왕은 Scheme의 `continuation`, 즉 `call-with-current-continuation(call/cc)`이 아닌가 싶다. 대체 이게 왜 필요한지, 그래서 이걸 알면
어디에 쓸 수 있다는 건지, 제대로 익히지 못하면 다음으로 넘어가지 못하는 것인지 알 수 없었다. 다행히 call/cc를 몰라도 사는 데에 큰 지장은 없으니
치명적인 건 아니다.

아무튼 `call/cc`는 정말 악명 높은 개념이다. 일단 이름부터 길다. 그리고 누구나 알 만한 쉬운 단어로 조립되어 있는데도, 처음 들어서는 대체 뭘 하자는 것인지 알쏭달쏭하다.
그런데 `call/cc`가 어려운 가장 큰 이유는 **문법이나 구현이 어려워서가 아니라, 우리가 평소 생각하는 함수의 개념 자체를 살짝 뒤집기 때문**이다.

거두절미하고 핵심을 짚어보자.

> **`call/cc`는 "지금 여기서부터 프로그램이 계속 진행할 방법"을 값으로 뽑아내는 기능"이다.**

그리고 그 "계속 진행할 방법"을 나중에 다시 호출할 수 있다.

이게 대체 무슨 말인가?

---

## Continuation에 대한 가벼운 이해

사실 이 개념은 프로그래밍을 아주 오래 한 사람들도 머리가 아프다고 말하는 정말 난해한 개념이다.
그래서 처음 이 개념을 접한 사람이 이해하기 힘들다고 느끼는 건 전혀 이상한 게 아니다. 그러니 일단 비유를 들어 가볍게 접근해보자.


### 'Continuation'이 무엇인가
`call/cc`는 **Call-with-Current-Continuation**의 줄임말이다. 여기서 'continuation'은 "**지금 이 순간부터 프로그램이 끝날 때까지 남은 일들(미래)**"을 뜻한다.

마치 책을 읽다가 '**지금 이 문장부터 책의 마지막까지**'를 통째로 오려내서 간직하는 것과 같다.

### 비유 1: 비디오 게임의 '세이브 포인트'
게이머가 비디오 게임을 한다고 상상해 보자. 보스전을 앞두고 저장 버튼을 누르면, 그 순간의 내 체력, 위치, 아이템 상태가 저장된다.

Scheme에서 `call/cc`를 쓰면, **"지금 이 순간의 프로그램 상태(남은 계산들)"를 통째로 세이브**해서 변수에 담아둘 수 있다.
나중에 이 세이브 데이터(continuation)를 불러오면, 마치 타임머신을 탄 것처럼 **그때 그 순간으로 돌아가서 계산을 이어서 하거나, 결과를 덮어씌울 수 있다.**

### 비유 2: 함수의 '비상구' (가장 간단한 개념)
사실 `call/cc`를 가장 쉽게 이해하는 방법은 "**함수 중간에서 강제로 빠져나가는 비상구**"로 생각하는 거다.

보통 함수는 맨 마지막에 다다르거나 `return`을 만나야 끝난다. 그런데 `call/cc`를 쓰면, 복잡한 계산 도중에 "아, 더 이상 계산할 필요 없어!" 하고 **함수 전체를 탈출**할 수 있다.

이걸 코드로 보면 간단하다:

```scheme
(call/cc
  (lambda (escape)      ; 'escape'라는 비상구 버튼을 받아온다.
    (display "1. 시작!\n")
    (escape "끝!")      ; 여기서 비상구 버튼을 누르면, 즉시 call/cc 전체의 결과로 빠져나간다!
    (display "2. 이건 출력되지 않는다.\n"))) ; escape를 만났으므로 이 코드는 영원히 실행되지 않는다.
```

보이는가? `Esc` 버튼을 누르는 순간, 뒤에 있는 모든 코드를 무시하고 `call/cc`의 최종 결과값으로 `"끝!"`을 뱉으며 탈출해 버린다. C언어나 자바의 `return`이나 `break`보다 훨씬 강력한 비상구인 셈이다.

### 비유 3: 타임머신 티켓 (조금 더 깊게)
방금 본 비상구는 티켓을 '그 자리에서' 쓴 거다. 하지만 `call/cc`의 진짜 무서운(그리고 아름다운) 점은 **이 티켓을 주머니에 넣고 나중에 쓸 수 있다는 거**다.

세이브 포인트(continuation)를 전역 변수 같은 곳에 보관해 두었다가, 프로그램이 한참 돌아간 뒤에 그 티켓을 꺼내 쓰면? 프로그램이 순식간에 과거의 그 세이브 포인트로 점프해 버린다. 시간을 되돌리는 타임머신과도 같다.

### 정리
`call/cc`는 딱 두 가지만 기억하면 된다.
1. **"남은 미래(continuation)를 스냅샷으로 찍어서 변수로 만든다."**
2. **"그 변수를 호출하면, 찍었던 그 순간으로 타임워프해서 값을 덮어쓰며 탈출한다."**

이 정도면 조금이나마 개념이 손에 잡힐까?

장담하건데 `call/cc`를 처음 접한 누군가가 이걸로 개념이 잡혔다고 하면 무조건 거짓말이다. 이제 continuation을 조금 더 진지하게 살펴보자.


---

## Continuation의 개념 깊게 들어가기

`continuation`이라는 말을 다시 살펴보자.

예를 들어:

```scheme
(+ 10 (* 2 3))
```

`(* 2 3)`을 계산하면 `6`이 나온다.

그러면 프로그램은:

```scheme
(+ 10 6)
```

을 계산해서 `16`을 얻는다.

여기서 `(* 2 3)`이라는 계산이 끝난 **바로 다음에 프로그램이 해야 할 일**은 무엇일까?

```scheme
(+ 10 6)
```

즉,

> "`6`이라는 값이 나오면 그것을 받아서 `+ 10`을 수행해라."

이것이 바로 **continuation**이다.

조금 더 함수처럼 표현하면:

```scheme
(lambda (x)
  (+ 10 x))
```

즉,

```text
(* 2 3)
    ↓
    6
    ↓
(+ 10 6)
    ↓
   16
```

여기서 `6` 이후의 나머지 계산을 함수로 표현한 것이 continuation이다.
<br/>
<br/>


**그런데 사실 우리가 평소에도 continuation을 만들고 있다.**

예를 들어 이런 코드가 있다고 해보자.

```scheme
(define (square x)
  (* x x))

(+ 100 (square 5))
```

`(square 5)`가 계산된 다음에는 무엇을 해야 할까?

```scheme
(+ 100 25)
```

따라서 그 시점의 continuation은 사실상:

```scheme
(lambda (x)
  (+ 100 x))
```

이다.

즉,

```scheme
(square 5)
```

를 계산하는 입장에서 보면 프로그램은 이렇게 말하는 셈이다.

> "네가 값을 하나 내놓으면 내가 그걸 가지고 `(+ 100 ...)`을 할게."

이게 continuation이다.
<br/>
<br/>

**그런데 보통 continuation은 직접 만질 수 없다.**

일반적인 Scheme 프로그램에서는 continuation이 **프로그램 실행 상태 안에 숨어 있다.**

예를 들어:

```scheme
(+ 100 (* 2 3))
```

현재 `(* 2 3)`을 실행하고 있다면 런타임은 대략 이런 정보를 가지고 있다.

```text
현재 계산:
    (* 2 3)

결과가 나오면:
    (+ 100 결과)

그 다음:
    프로그램 종료
```

하지만 우리는 저 "결과가 나오면 나머지 계산을 해라"라는 것을 직접 가져올 수는 없다.  그런데 Scheme은 여기서 아주 미친 기능을 하나 제공한다.
<br/>
<br/>

### `call/cc`는 `continuation`을 꺼내준다.

개념적으로:

```scheme
(call/cc f)
```

는 이렇게 생각하면 된다.

> "**현재 프로그램의 continuation을 하나 만들어서 `f`에게 줘.**"

예를 들어:

```scheme
(call/cc
  (lambda (k)
    ...))
```

여기서 `k`가 바로 continuation이다.

그리고 `k`를 함수처럼 호출할 수 있다.

```scheme
(k value)
```

그러면 무슨 일이 일어날까?

> **현재 위치에서의 계산을 버리고, `k`가 기억하고 있던 지점으로 돌아간다.**

이게 `call/cc`의 본체다.
<br/>
<br/>

**아주 단순한 예를 들어보자.**

```scheme
(+ 10
   (call/cc
     (lambda (k)
       20)))
```

여기서 `call/cc`가 실행되는 순간 continuation은:

```scheme
(lambda (x)
  (+ 10 x))
```

이다.

그리고 이것을 `k`라고 하자.

그러면 내부는 사실상:

```scheme
(lambda (k)
  20)
```

이고 `k`는:

```scheme
(lambda (x)
  (+ 10 x))
```

이다.

따라서 `call/cc`의 결과는 `20`,

결국:

```scheme
(+ 10 20)
```

이 되어:

```text
30
```

이 나온다.

여기까지는 별로 이상하지 않다.
<br/>
<br/>

**진짜 이상한 건 continuation을 호출할 때다.**

이번에는:

```scheme
(+ 10
   (call/cc
     (lambda (k)
       (k 20))))
```

을 보자.

`call/cc`가 실행되었을 때 현재 continuation은:

```scheme
(lambda (x)
  (+ 10 x))
```

이다.

그걸 `k`에 넣어준다.

그래서:

```scheme
(k 20)
```

은 사실상:

```scheme
(+ 10 20)
```

을 실행하라는 뜻이다.

결과:

```text
30
```
<br/>

### 그렇다면 k는 함수인가?

그런데 여기서 중요한 사고방식, `k`를 **함수라고 생각하면 안 되는 순간**이 온다.

물론 Scheme 문법상으로는 함수처럼 호출한다. 하지만 의미적으로는 일반 함수와 다르다.

일반 함수:

```scheme
(define (f x)
  (+ x 10))
```

를 호출하면:

```scheme
(f 20)
```

현재 함수에서 `f`를 호출하고, `f`가 끝나면 **원래 함수의 다음 부분으로 돌아온다.**

반면 continuation:

```scheme
(k 20)
```

은

> "`k`가 저장하고 있던 프로그램의 실행 위치로 **점프하라**."

에 가깝다.

그래서 `call/cc`는 함수 호출이라기보다 **실행 흐름을 값으로 만들어서 저장하고, 나중에 그 흐름으로 점프하는 것**에 가깝다.
<br/>
<br/>


### 결국 함수와 무엇이 다른가?

이제 드디어 함수와 continuation이 달라지는 부분이다.

```scheme
(call/cc
  (lambda (exit)
    (display "A")
    (exit 42)
    (display "B")))
```

출력은:

```text
A
```

뿐이다. `B`는 출력되지 않는다.

왜냐하면:

```scheme
(exit 42)
```

하는 순간 `exit`가 가지고 있던 continuation으로 **점프해 버렸기 때문**이다.

따라서:

```schem이
(display "B")
```

까지 정상적으로 진행하지 않는다. 이 때문에 continuation을 흔히:

> **조기 탈출(early exit/return)**

처럼 사용하기도 한다.
<br/>
<br/>

### 이것은 사실 우리가 익숙한 `return`과 굉장히 비슷하다.

이제 조금 감이 잡힐 것이다.

예를 들어 일반적인 언어에서:

```rust
fn foo() -> i32 {
    println!("A");
    return 42;
    println!("B");
}
```

`return 42`를 만나면 현재 함수의 나머지 실행을 버리고 호출자에게 돌아간다.

`call/cc`는 이것을 훨씬 일반화한 것이다.

`return`은:

> "현재 함수에서 빠져나간다."

라는 **고정된 continuation**을 사용하는 것이라 볼 수 있다.

반면 `call/cc`는:

> "현재 프로그램의 continuation을 내가 직접 값으로 가지고 있겠다."

이다.

그래서 continuation을 저장할 수도 있다.

```scheme
(define saved #f)

(call/cc
  (lambda (k)
    (set! saved k)
    42))
```

이제 `saved`에는 **그 시점의 프로그램을 이어서 실행할 방법**이 들어 있다.

그리고 나중에:

```scheme
(saved 100)
```

이라고 하면 그 당시의 continuation으로 돌아간다.
<br/>
<br/>


**그래서 `call/cc`가 특별해진다.**

보통 함수는:

```text
호출
 ↓
실행
 ↓
return
 ↓
호출자로 복귀
```

라는 구조이다.

그런데 continuation은:

```text
어떤 시점의 프로그램 상태
        ↓
   continuation
        ↓
       저장
        ↓
    나중에 호출
        ↓
그 당시의 실행 흐름으로 복귀
```

가 가능하다.

그래서 단순한 `return`뿐 아니라,

* 예외 처리
* 조기 탈출
* 코루틴
* backtracking
* generator
* cooperative multitasking
* coroutine
* non-local control flow

같은 것들을 구현할 수 있다. 정말로 만능 유틸리티다.
<br/>
<br/>

**그리고 여기서 가장 중요한 관점 전환이 필요하다.**

`call/cc`를 이해하기 위해 딱 하나만 머릿속에 넣으라고 한다면 이것이다.

**일반적인 함수:**

```text
값을 받는다
   ↓
계산한다
   ↓
값을 반환한다
```

**continuation:**

```text
"여기서 계산이 끝나면 무엇을 할 것인가?"
```

를 나타낸다.

그리고 `call/cc`는

> "지금 여기서부터 프로그램이 계속 진행될 방법을 함수 형태의 값으로 나에게 줘."

이다.

그래서:

```scheme
(k x)
```

는 단순히

```text
k라는 함수를 호출한다
```

가 아니라,

```text
k가 저장하고 있던 "프로그램을 계속 진행하는 방법"을 x라는 값으로 실행한다
```

라고 이해하는 게 훨씬 정확하다.

## 마치며

내가 **Haskell의 Monad와 Rust의 스마트 포인터 `Box/Deref/Rc/Arc/RefCell`까지는 어떻게든 붙잡는데 `call/cc`에서 유독 막혔던** 부분이 이런 것 때문이다. 스마트 포인터는 결국 소유권/수명/참조 카운팅이라는 **객체의 상태**를 이해하면 되고, Monad도 결국 **계산을 조합하는 구조**로 내려가면 잡히는데, `call/cc`는 아예 "**프로그램 실행 자체를 값으로 취급한다**"는 발상을 해야 하기 때문이다.

자 이 정도로 continuation을 개념적으로나마 알아보았다. 다음 글에서는 `call/cc`를 그냥 설명으로 이해하기보다, Scheme 코드 하나를 한 줄씩 실행하면서 "**이 순간 continuation이 정확히 무엇인가**"를 추적해보자.
