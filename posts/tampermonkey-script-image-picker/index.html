웹 브라우저를 사용하다 보면 기본 제공되는 기능이 뭔가 아쉬울 때가 있다. 이럴 때 많이 찾는 것이 브라우저 확장 프로그램(extension)인데, 내가 필요한 용도로 쓸 만한 확장 프로그램을 찾으면 좋겠지만, 어떨 땐 아무리 찾아도 내가 필요로 하는 기능을 가진 것을 못 찾을 때가 있다. 그럴 땐 어쩔 수 없이 만들어 써야지 별 수 있나.

그런데 이 경우에도 두 가지 선택지가 있다. 하나는 웹 브라우저 확장 프로그램, 또 하나는 Greasemonkey 또는 Tampermonkey 같은 사용자 스크립트 관리 프로그램 위에서 돌아가는 사용자 스크립트이다. 우선 이 둘을 비교해보자.

쉽게 말하면 웹 브라우저 확장 프로그램은 브라우저에 설치하는 정식 플러그인이고, Greasemoney/Tampermonkey 스크립트는 웹페이지 위에서 돌아가는 사용자 자바스크립트 조각이라는 차이가 있다.

참고로, “Greasemonkey”는 원래 파이어폭스용 사용자 스크립트 관리 확장이고, 크롬에서는 보통 Tampermonkey, Violentmonkey 같은 사용자 스크립트 관리 확장으로 비슷한 기능을 사용한다.

조금 더 풀어서 설명하면 이렇다.

1. 웹 브라우저 확장 프로그램
#

웹 브라우저 확장 프로그램은 브라우저 기능을 확장하는 정식 애플리케이션이다. 보통 manifest.json 파일을 중심으로 구성되고, 필요에 따라 다음 같은 요소를 가질 수 있다.

  • 콘텐츠 스크립트: 특정 페이지에서 DOM을 수정하거나 기능을 추가
  • 백그라운드 스크립트 또는 서비스 워커: 브라우저가 열려 있는 동안 백그라운드 작업 수행
  • 팝업 UI: 확장 아이콘을 눌렀을 때 나오는 작은 창
  • 옵션 페이지: 사용자가 설정을 바꿀 수 있는 화면
  • 브라우저 API 접근: 탭, 쿠키, 저장소, 알림, 네트워크 요청 등

예를 들어, 비밀번호 관리자, 광고 차단기, 번역 확장, 개발자 도구 같은 것은 확장 프로그램으로 만드는 경우가 많다.

2. Greasemonkey 스크립트 / 유저스크립트
#

Greasemonkey 스크립트는 특정 웹사이트에 주입되는 자바스크립트 파일이다. 보통 이런 머리말을 포함한다.

// ==UserScript==
// @name         예제 스크립트
// @namespace    example
// @version      1.0
// @match        https://example.com/*
// @run-at       document-end
// ==/UserScript==

console.log("유저스크립트가 실행되었습니다.");

여기서 @match는 어떤 사이트에서 실행될지를 정하고, @run-at은 페이지 로딩 중 어느 시점에 실행할지를 정한다.

유저스크립트는 보통 다음 같은 일에 적합하다.

  • 특정 사이트의 UI 수정
  • 귀찮은 작업 자동화
  • 페이지 일부 요소 숨기기
  • 단축키 추가
  • 특정 사이트 전용 기능 개선
  • 간단한 스크래핑이나 텍스트 변환

3. 결정적인 차이
#

가장 큰 차이는 권한과 구조다.

웹 브라우저 확장 프로그램은 브라우저와 더 깊게 통합될 수 있다. 예를 들어 탭 정보를 읽거나, 브라우저 저장소를 쓰거나, 알림을 띄우거나, 네트워크 요청을 가로채는 등의 일을 할 수 있다.

반면 유저스크립트는 기본적으로 현재 웹페이지 안에서의 자바스크립트 실행에 가깝다. 물론 Tampermonkey의 GM_xmlhttpRequest, GM_setValue, GM_notification 같은 API를 쓰면 일반 페이지 스크립트보다 더 많은 일을 할 수 있지만, 그래도 정식 웹 브라우저 확장만큼 폭넓은 브라우저 권한을 갖지는 않는다.

조금 더 자세히 살펴보면,

웹 브라우저 확장 프로그램
#

웹 브라우저 확장 프로그램은 브라우저에 직접 설치되는 기능이기 때문에, 개발자가 원하면 다음과 같은 권한을 요청할 수 있다.

  • 현재 열린 탭 정보 읽기
  • 브라우저 저장소 사용
  • 쿠키 읽기/쓰기
  • 특정 사이트 또는 모든 사이트에서 스크립트 실행
  • 네트워크 요청 관찰 또는 수정
  • 알림 표시
  • 브라우저 메뉴, 아이콘, 팝업, 설정 페이지 제공
  • 다운로드, 북마크, 방문 기록 등 브라우저 기능 접근

물론 실제로 어느 정도 권한을 갖는지는 그 확장이 manifest.json에서 어떤 권한을 요청했는지에 따라 다르다.

사용자 스크립트
#

사용자 스크립트는 본래 특정 웹페이지 안에서 동작하는 자바스크립트에 가깝다. 그래서 기본적으로는 해당 페이지의 DOM, 즉 화면에 보이는 요소들을 조작하는 수준의 일을 한다.

다만 Greasemonkey, Tampermonkey 같은 사용자 스크립트 관리 확장에는 특별한 API가 있다.

예를 들면:

  • GM_xmlhttpRequest: 페이지의 같은 도메인 제한을 넘어서 요청 보내기
  • GM_setValue / GM_getValue: 스크립트 전용 저장 공간에 값 저장
  • GM_notification: 알림 표시
  • GM_openInTab: 새 탭 열기
  • GM_setClipboard: 클립보드에 복사

이런 기능은 일반 웹페이지 자바스크립트보다는 더 강력한 기능이다. 하지만 이것도 결국 Tampermonkey나 Greasemonkey 같은 확장 프로그램이 대신 제공해 주는 권한이다.

그래서 비교하자면
#

항목웹 브라우저 확장 프로그램사용자 스크립트
브라우저 API 직접 사용가능보통 불가
탭, 쿠키, 북마크 등 접근권한 요청 시 가능직접은 어려움
백그라운드 작업가능제한적
페이지 DOM 조작가능가능
설치 난이도상대적으로 복잡간단
권한 범위매우 넓게 확장 가능관리자 확장에 의존

즉, 웹 브라우저 확장 프로그램은 브라우저 자체와 더 깊게 연결될 수 있는 공식적인 방법이고, Greasemonkey 스크립트는 특정 페이지에 끼워 넣는 가벼운 스크립트에 가깝다.

단, 예외도 있다
#

재미있는 점은, 실제로는 유저스크립트 관리자 확장, 예를 들어 Tampermonkey가 이미 꽤 강력한 권한을 가지고 있을 수 있다는 거다.

만약 Tampermonkey가 “모든 사이트에서 실행” 권한을 가지고 있고, 사용자가 설치한 스크립트가 GM_xmlhttpRequest 같은 기능을 사용한다면, 외부 서버로 요청을 보내거나 로컬에 값을 저장하는 일도 가능하다.

그래서 “유저스크립트는 항상 약하고 안전하다"라고 단정하기는 어려워요. 유저스크립트도 악성 스크립트를 설치하면 해당 사이트에서 입력한 내용이나 페이지 정보를 읽을 수 있다.

4. 어떤 걸 선택하면 좋을까?
#

간단하게 정리하면 이렇게 생각할 수 있다.

유저스크립트가 적합한 경우
#

  • 특정 사이트 하나에서만 동작하게 하고 싶을 때
  • 빠르게 만들고 설치하고 싶을 때
  • 페이지 요소 수정 정도의 기능이 필요할 때
  • 복잡한 브라우저 권한이 필요 없을 때

예:

// 특정 사이트에서 제목 색 바꾸기
document.title = "수정된 제목";
document.body.style.backgroundColor = "#111";

웹 브라우저 확장 프로그램이 적합한 경우
#

  • 여러 사이트에서 광범위하게 동작해야 할 때
  • 브라우저 탭, 쿠키, 저장소, 알림 같은 기능을 사용해야 할 때
  • 팝업, 설정 페이지, 백그라운드 처리가 필요할 때
  • Chrome Web Store에 정식으로 배포하고 싶을 때

5. 보안 관점
#

둘 다 조심해야 한다. 확장 프로그램은 강력한 권한을 가질 수 있기 때문에 악성 확장이 설치되면 브라우저 데이터에 광범위하게 접근할 수 있다.

유저스크립트도 페이지에 직접 주입되는 코드이기 때문에, 악성 스크립트를 설치하면 해당 페이지에서 입력한 값이나 쿠키, DOM 내용을 읽을 수 있다. 특히 은행, 이메일, SNS 같은 사이트에서 동작하는 유저스크립트는 더 조심하는 게 좋다.

그러니까 사용자가 만약 “특정 사이트에서 간단한 편의 기능을 추가하고 싶다"면 유저스크립트가 편하고, “브라우저 전체나 여러 사이트에서 본격적인 기능을 만들고 싶다"면 웹 브라우저 확장 프로그램이 더 적합하다고 보면 된다.

6. 사용자 스크립트의 구현: Image Picker
#

웹 서핑을 하다가 마음에 드는 이미지를 내 컴퓨터에 내려받고 싶을 때가 있다. 이 경우 보통은 마우스로 이미지를 클릭한 다음에 “다른 이름으로 저장"하기를 통해 이미지를 내려받는다. 그런데 내 컴퓨터에 이미지를 내려받으면 다른 컴퓨터에서 사용하고 싶을 때 다시 이것을 이미지 클라우드에 올려야 한다. 그래서 웹 페이지의 이미지를 클릭만 하면 내 컴퓨터에 해당 이미지를 내려받지 않고 바로 이미지 클라우드에 저장하는 기능이 필요했다.

이 기능을 구현하기 위해 웹 브라우저 확장 프로그램을 만들지, 아니면 Tampermonkey 사용자 스크립트를 만들지를 먼저 결정해야 한다. 둘 다 기능 구현에 문제가 없다. 그렇다면 번거롭게 확장을 만들기 보다는 사용자 스크립트로 만들어보자.

스크립트 개요
#

웹페이지에서 이미지를 클릭하면 해당 이미지를 클라우드 imgbb에 업로드하고 업로드된 URL을 획득하는 Tampermonkey 스크립트.

동작 방식
#

  1. 우측 상단 📷 Pick 버튼을 클릭하여 활성화
  2. 활성화되면 버튼이 빨간색(#ef4444)으로 변경되고 📷 Active 표시
  3. 마우스가 <img> 요소 위로 이동하면 파란색 하이라이트(3px 테두리 + 반투명 배경) 표시
  4. 이미지 클릭 시:
    • img.currentSrc || img.src로 URL 획득
    • API 키가 없으면 prompt()로 입력 요청 후 GM_setValue에 저장
    • GM_xmlhttpRequest로 imgbb API 호출 (POST https://api.imgbb.com/1/upload?key=...&image=...)
    • 성공 시 모달로 업로드된 이미지 URL 표시 (클릭 가능한 링크)
    • 실패 시 오류 메시지 표시
  5. 이미지 선택 후 자동 비활성화

주요 구성 요소

함수/변수설명

@grant 권한
#

  • GM_xmlhttpRequest — CORS 우회 HTTP 요청
  • GM_getValue / GM_setValue — API 키 영구 저장

@match 설정
#

  • *://*/* — 모든 사이트에서 동작

업데이트 URL
#

  • @updateURL 및 @downloadURL은 GitHub Gist raw URL을 사용

API 키 관리
#

  • 최초 1회 prompt()로 입력, 이후 GM_setValue('imgbb_api_key', ...)로 자동 저장
  • Tampermonkey 대시보드 → 값 탭에서 직접 수정/삭제 가능

스크립트 소스 코드
#

이렇게 Tampermonkey 사용자 스크립트를 만들어 보았다.

나중에 기회가 된다면 기능을 더 추가하고 싶은데 그게 언제가 될지는 기약할 수 없다. 만약 여기서 기능을 더 넣는다면

  1. 이미지 외 요소(링크, 텍스트 등) pick 지원
  2. 업로드 히스토리 표시
  3. API 키 재설정 기능
  4. 여러 이미지 연속 선택 모드
  5. 이미지 drag & drop pick 지원

등이 필요할 것 같다.

이외에도 내가 주로 Tampermonkey를 사용하는 용도는 광고 차단 확장 프로그램만으로는 차단할 수 없는 광고를 차단하는 것이다. 광고 차단 확장은 “사용자 정의 규칙"을 넣을 수 있긴 한데, 기껏 우리가 할 수 있는 것은 DOM에서 id나 class를 이용해서 광고 요소를 찾는 것 뿐이다. 만약 웹 페이지가 복잡한 규칙을 가지고 광고를 뿌린다면 우리도 거기에 대응하는 복잡한 조건식을 만들어야 한다. 이 때 Tampermonkey를 이용하면 좋다.
